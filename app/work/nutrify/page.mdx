<En>
**In ten seconds:** logging food by hand is why diet apps fail. Nutrify identifies a
meal from a photo, estimates the portion, computes calories and macros, and tells you
whether it fits your goal — cut, bulk, or maintain. Flutter app, FastAPI backend,
multi-model ML pipeline running locally.

## Problem

Calorie tracking works — if you do it. Manual logging is tedious enough that most
people quit within weeks. The friction isn't knowledge; it's data entry.

## Solution

Point the camera at your food. Nutrify detects what's on the plate, classifies it,
estimates the portion size, and computes calories and macronutrients. It then compares
those numbers against your daily target and answers the question you actually have:
*does this meal fit my goal?*

A Gemini-powered chat assistant handles follow-up questions; the recognition pipeline
itself runs locally and needs no API key.

## Architecture

```text
Flutter app (camera + UI)
        │  photo
        ▼
FastAPI backend — ML orchestration
├─ detection model        what items are in the frame
├─ classification model   which food each item is
├─ portion estimation     how much of it there is
├─ nutrition database     calories + macros per unit
└─ recommendation engine  verdict vs. daily target (cut / bulk / maintain)
```

Three parts with clean seams: Flutter owns capture and presentation, FastAPI owns
orchestration, and the pipeline composes multiple specialized models rather than
betting everything on one end-to-end network. Trained on three public Kaggle food
datasets; notebooks in the repo are generated from the Python training scripts.

## Decisions & tradeoffs

- **Pipeline over monolith.** Detection, classification, and portion estimation are
  separate stages — each can be improved or swapped independently, and failures are
  diagnosable per stage.
- **Local inference.** The recognition path has no external API dependency, so the
  core feature works without keys, quotas, or per-request cost. Only the optional chat
  assistant calls out.
- **Verdict, not dashboard.** The end of the pipeline is a recommendation against the
  user's goal, not a wall of numbers — the product insight is that people want an
  answer, not a spreadsheet.

## Status

University team project at capstone scale. Functional pipeline end-to-end; no
published accuracy benchmarks or usage metrics, and it's presented as exactly that.

<Id>
**Dalam sepuluh detik:** mencatat makanan secara manual membuat aplikasi diet sering ditinggalkan. Nutrify mengenali hidangan dari foto, mengestimasi porsi, menghitung kalori & makro, serta memberi tahu apakah hidangan tersebut sesuai target Anda — cut, bulk, atau maintain. Aplikasi Flutter, backend FastAPI, alur ML multi-model yang berjalan secara lokal.

## Masalah

Pelacakan kalori terbukti efektif — jika dilakukan secara konsisten. Pencatatan manual cukup menyita waktu sehingga kebanyakan orang menyerah dalam hitungan minggu.

## Solusi

Arahkan kamera ke makanan Anda. Nutrify mendeteksi objek di piring, mengklasifikasikannya, mengestimasi ukuran porsi, serta menghitung kalori dan nutrisi makro. Kemudian membandingkannya dengan target harian Anda untuk menjawab pertanyaan utama: *apakah makanan ini sesuai dengan target saya?*

Asisten percakapan berbasis Gemini menangani pertanyaan lanjutan; alur pengenalan utama berjalan secara lokal tanpa memerlukan API key eksternal.

## Arsitektur

```text
Aplikasi Flutter (kamera + UI)
        │  foto
        ▼
Backend FastAPI — Orkestrasi ML
├─ model deteksi         objek apa saja di dalam bingkai
├─ model klasifikasi     jenis makanan setiap objek
├─ estimasi porsi        seberapa banyak jumlahnya
├─ basis data nutrisi    kalori + makro per unit
└─ mesin rekomendasi     analisis vs. target harian (cut / bulk / maintain)
```

## Keputusan & Kompromi

- **Alur terpisah dibanding monolith.** Deteksi, klasifikasi, dan porsi adalah tahap terpisah yang mudah diperbarui secara independen.
- **Inferensi lokal.** Proses pengenalan utama tidak memiliki ketergantungan API eksternal, sehingga fitur inti bekerja tanpa batas kuota.
- **Keputusan langsung, bukan sekadar dasbor.** Hasil akhir memberikan saran konkret sesuai target pengguna, bukan sekadar tumpukan angka.

## Status

Proyek tim universitas skala tugas akhir. Alur berfungsi penuh dari hulu ke hilir.
