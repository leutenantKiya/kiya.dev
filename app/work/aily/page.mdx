<En>
**In ten seconds:** most store questions are routine, but answering them still takes
staff. AILY parses natural-language messages and routes each one to the right
handler — product search, cart, checkout, order tracking — and answers automatically.
Python NLP service, Java desktop client, SQL storage.

## Problem

E-commerce support is dominated by a small set of repetitive intents: where is my
order, do you have X, how do I pay. Humans answering those don't scale, and generic
chatbots that try to handle everything in one blob fail unpredictably.

## Solution

A pipeline with one job per stage:

```text
User / Admin input
  → FastAPI endpoint  (role-separated: /aily/user/…  /aily/admin/…)
  → key validation    (id + public key per role; invalid → rejected)
  → NLP processing
  → intent router
  → one of 11 handlers
  → response
```

Eleven specialized handlers, each owning one intent family: FAQ, product search,
product detail, cart, checkout, order status, order processing, logistics tracking,
store profile, admin product CRUD, and a fallback for anything unparseable. User and
admin traffic enter through separate authenticated endpoints — an admin managing the
catalog goes through the same NLP front door as a customer asking about shipping.

## Decisions & tradeoffs

- **Router + handlers over one model.** Decomposing by intent makes each handler
  small, testable, and independently replaceable — and the fallback handler makes the
  failure mode explicit instead of hallucinated.
- **Cross-language by contract.** The Python NLP service and the JavaFX client meet at
  a plain HTTP API — each side uses the language that suits it (Python for NLP, Java
  for the coursework's desktop requirements).
- **Key-per-role auth.** Simple id + public-key validation separates user and admin
  capabilities at the entry point, before any intent logic runs.

## Status

University team project, presented architecture-first: the intent-router design is the
substance here. The repo shows a staged build plan with substantial Java and Python
implementation; no deployment or usage metrics.

**Dalam sepuluh detik:** sebagian besar pertanyaan pelanggan toko bersifat rutin, tetapi tetap membutuhkan staf untuk menjawabnya. AILY menganalisis pesan bahasa alami dan mengarahkan masing-masing pesan ke handler yang tepat — pencarian produk, keranjang, pembayaran, hingga pelacakan pesanan — dan menjawab secara otomatis. Layanan NLP Python, klien desktop Java, penyimpanan SQL.

## Masalah

Dukungan e-commerce didominasi oleh sekumpulan niat yang berulang: di mana pesanan saya, apakah stok X ada, bagaimana cara bayar. Penanganan manual oleh manusia kurang efisien, sementara chatbot generik serba-bisa sering kali tidak akurat.

## Solusi

Alur kerja dengan satu tugas khusus per tahap:

```text
Input Pengguna / Admin
  → Endpoint FastAPI  (terpisah peran: /aily/user/…  /aily/admin/…)
  → Validasi Kunci    (id + kunci publik per peran)
  → Pemrosesan NLP
  → Router Niat
  → 1 dari 11 Handler Khusus
  → Respons
```

Sebelas handler khusus menangani kelompok niat tertentu: FAQ, pencarian produk, detail produk, keranjang, pembayaran, status pesanan, pemrosesan pesanan, pelacakan logistik, profil toko, CRUD produk admin, serta fallback untuk pesan yang tak terurai.

## Keputusan & Kompromi

- **Router + handler dibanding satu model tunggal.** Memecah niat membuat setiap handler berukuran kecil, teruji, dan dapat diperbarui secara independen.
- **Antar-bahasa berdasarkan kontrak API.** Layanan NLP Python dan klien JavaFX terhubung melalui HTTP API sederhana.

## Status

Proyek tim universitas dengan fokus utama pada arsitektur sistem.
